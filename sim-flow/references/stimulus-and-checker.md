# 用例与 checker：证伪、分层、随机纪律

## checker 证伪（软约束：默认要做，豁免留痕，未证伪降级）

checker 有效性是整套平台的地基：checker 抓不到错，一万个 PASS 都是假绿。
证伪不是前置硬门禁，但证据等级与之绑定：

1. **默认动作**：每个 checker 配"必然失败"的反向激励，确认它真的报警。
   允许一条反向激励同时证伪多个 checker（如一次反压改数同时证伪
   hold 类与协议类 checker）。
2. **豁免**：恒等/连线类等结构平凡 checker 可豁免证伪；豁免与理由必须
   在 VP 表或用例注释留痕。
3. **报警质量**（硬要求）：报警信息必须包含仿真时间、期望值、实际值——
   只打 "mismatch" 的 checker 不合格。
4. **证据等级**：未证伪且未豁免的 checker 判出的 PASS 是未证实证据——
   VP 可凭它到 passing，**不得凭它 closed**；closed 要求 checker 已证伪
   或已豁免。证伪/豁免记录进 VP 表或用例注释。

## 用例分层（固定推进顺序）

1. **定向**：每条契约条款、每个功能项、边界值（0/1/max-1/max/超限）、
   非法输入（按 spec 的 illegal_inputs 逐项验）。定向用例的
   激励是精确构造的；纯定向 seed 写 `fixed`，含随机段的按随机纪律节
   的口径配 `random`。
2. **约束随机**：组合空间、多拍交织、反压模式——定向穷举不完的部分。
   约束从 spec 的契约推导，非法输入不进随机池（非法输入走定向）。
3. **历史 BUG 复现**：每个修过的 BUG 留一个回归用例，防回潮。

## 激励强度：循环、交织与零气泡边界

1. **循环证对，非单笔证对**：一个功能场景在用例内循环多笔（数据/地址/
   形态逐笔变化），每笔都经 monitor→scoreboard 比对——只跑一笔证明的
   是"存在一条正确路径"，不是"功能正确"。循环量级写进用例注释并可调
   （参数/环境变量），加压不改代码。
2. **交织维度矩阵**：先把激励的可变维度列全——典型有：方向（读/写）、
   访问类型（如独占/普通）、写掩码（全写/部分写/zero）、burst 长度、
   数据宽度、地址关系（新地址/同地址依赖）、反压模式。切换类 bug 出在
   维度换向处：构造**两两换向对**（读↔写、独占↔非独占、部分写↔全写、
   同地址依赖……），每对双向都要。
3. **边界必中，不交给概率**：最短事务（1 拍 burst）等边界形态在随机池
   里命中率低且无命中确认，必须**强制插入**——换向对确定性排入用例，
   对间填随机事务作变化上下文：确定的是"必中边界"，随机的是"包围边界
   的上下文"。
4. **零气泡激励**：功能切换的压力峰值在相邻拍连续成交时出现。driver 应
   支持链式背靠背发射（成交沿直接换下一笔、valid 不撤），并用于换向对
   与随机长链；若主事务 API 逐笔串行 await（笔间必空拍），它只能证
   功能正确，证不了切换边界。
5. **零气泡 ≠ 成交相邻**：激励侧 valid 全程保持即为真零气泡；成交间隔
   被 DUT 合法反压（ready 拉低）拉开不是激励断档（spec 允许任意拍反压
   时，反压是 DUT 的权利）。证据中区分二者：valid 保持归激励，ready
   反压归 DUT；需要"无反压全类型相邻成交"证据时，关反压跑专项定向。

## 随机纪律

- **seed 必记**：cocotb 2.x 用 `COCOTB_RANDOM_SEED`（旧变量
  `RANDOM_SEED` 已废弃，用例读取用双变量回退链）；每次跑随机，seed
  进日志文件名。不记 seed 的随机失败等于没发生——无法复现就无法定位。
- **fixed/random 口径**：含随机段的用例配 `seed: random`——每轮回归
  激励不同，累积覆盖扩大；seed 落盘（日志名/status.yaml）+ 复现命令
  保证可追溯，不比 fixed 差。激励完全写死的纯定向用例保持 `fixed`。
  禁忌：含随机段却钉 fixed——"随机流"逐字节恒定等同定向，自以为在跑
  随机。
- **意图与实际分开记**：随机场景同时记录"生成了什么"（sequence/driver
  侧）和"实际接受了什么"（monitor 侧），二者不一致本身可能就是问题。
- 随机用例同样要有明确 checker；不允许"随机跑一遍没崩就算过"。

## 非法输入的处理

- 按 spec 的 `illegal_inputs` 逐项定向验：约定"忽略"就验忽略，
  约定"报错"就验报错标志。
- 约定"未定义"的：不做功能判定，但要验**不挂死**（后续正常事务仍能完成）。
