# 用例与 checker：证伪、分层、随机纪律

## checker 证伪（软约束：默认要做，豁免留痕，未证伪降级）

checker 有效性是整套平台的地基：checker 抓不到错，一万个 PASS 都是假绿。
证伪不是前置硬门禁，但证据等级与之绑定：

1. **默认动作**：每个 checker 配"必然失败"的反向激励，确认它真的报警。
   允许一条反向激励同时证伪多个 checker（如一次反压改数同时证伪
   hold 类与协议类 checker）。
2. **豁免**：恒等/连线类等结构平凡 checker 可豁免证伪；豁免与理由必须
   在 VP 表或用例注释留痕。
3. **报警质量**（硬要求）：报警信息必须包含仿真时间、期望值、实际值——
   只打 "mismatch" 的 checker 不合格。
4. **证据等级**：未证伪且未豁免的 checker 判出的 PASS 是未证实证据——
   VP 可凭它到 passing，**不得凭它 closed**；closed 要求 checker 已证伪
   或已豁免。证伪/豁免记录进 VP 表或用例注释。

## 用例分层（固定推进顺序）

1. **定向**：每条契约条款、每个功能项、边界值（0/1/max-1/max/超限）、
   非法输入（按 spec 的 illegal_inputs 逐项验）。定向用例的
   激励是精确构造的，seed 写 `fixed`。
2. **约束随机**：组合空间、多拍交织、反压模式——定向穷举不完的部分。
   约束从 spec 的契约推导，非法输入不进随机池（非法输入走定向）。
3. **历史 BUG 复现**：每个修过的 BUG 留一个回归用例，防回潮。

## 随机纪律

- **seed 必记**：cocotb 用 `RANDOM_SEED`/`seed` 参数；每次跑随机，seed
  进日志文件名。不记 seed 的随机失败等于没发生——无法复现就无法定位。
- **意图与实际分开记**：随机场景同时记录"生成了什么"（sequence/driver
  侧）和"实际接受了什么"（monitor 侧），二者不一致本身可能就是问题。
- 随机用例同样要有明确 checker；不允许"随机跑一遍没崩就算过"。

## 非法输入的处理

- 按 spec 的 `illegal_inputs` 逐项定向验：约定"忽略"就验忽略，
  约定"报错"就验报错标志。
- 约定"未定义"的：不做功能判定，但要验**不挂死**（后续正常事务仍能完成）。
